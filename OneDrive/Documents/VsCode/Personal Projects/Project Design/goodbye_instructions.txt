 3) ESP32 — SENSOR + RELAY (firmware + flashing)
--------------------------------------------------------------------------------
TWO ESP32s, two jobs, talking wirelessly through the backend (no wire between
them, so the noisy 12V ground never reaches the clean analog sensor).

FIRMWARE FILES (in ...\esp32-firmware\):
| Node   | HOME build (house WiFi)        | SCHOOL build (phone hotspot)          |
|--------|--------------------------------|---------------------------------------|
| Sensor | SHELVY_ESP1_SENSOR             | SHELVY_ESP1_SENSOR_5Ghotspot          |
| Relay  | SHELVY_ESP2_RELAY_25           | SHELVY_ESP2_RELAY_5Ghotspot           |
Only the WiFi differs. HOME = "Bawal  Connect!" (two spaces). SCHOOL = "Bawal Connect! 5g".

KEY SETTINGS (relay):
  - target 25.0 C (cools until 25, relay OFF 30s, repeat)
  - Peltier pins: IN1 -> GPIO 32, IN2 -> GPIO 33
  - RELAY_BOARD_ACTIVE_LOW = true  (BLUE OPTO board = triggers on LOW)
  - load on COM + NC (cooling ON by default)

SENSOR wiring (SHT30 / DFR0588 analog):
  VCC -> 3V3    T -> GPIO34    RH -> GPIO35    GND -> GND
  Power: POWER BANK to USB-C (isolated, do NOT tie to 12V ground)
  Calibration in code: TEMP_CAL_OFFSET=0.8, HUMI_CAL_OFFSET=-2.1

PINS TO REMEMBER:
  - 34/35/36/39 = INPUT ONLY -> good for the sensor, CANNOT drive a relay
  - 32/33/25/26/27/14 = output OK -> use for relay IN pins
  - AVOID for relay: 0,2,12,15 (strapping) · 1,3 (USB serial) · 6-11 (flash)

FLASH RECIPE (Arduino IDE, board = "ESP32 Dev Module"):
  1. Flash the ESP32 BARE (off the expansion board) to avoid failures
  2. Tools -> Upload Speed -> 115200
  3. Tools -> Erase All Flash Before Sketch Upload -> Enabled
  4. CLOSE the Serial Monitor (or upload fails: "port busy")
  5. Click Upload; if it hangs on "Connecting...", HOLD the BOOT button
  6. Success = "Hash of data verified" + "Hard resetting via RTS pin"
  7. Reconnect to the expansion board + wiring AFTER a clean flash

POWER RULE:  Buck OUTPUT = 5.0V -> ESP32 5V/VIN pin (NEVER 12V, NEVER 3V3-in).
             Red power LED ON = powered right.

WHICH FIRMWARE IS ON A BOARD? Open Serial Monitor (115200), press EN:
  [ESP1] SENSOR NODE ...  = sensor firmware
  [ESP2] RELAY NODE ...   = relay firmware

 4) RELAY WIRING — BOARD A: 6-CH 12V OPTO (blue, 2 grounds)  <-- USE THIS
--------------------------------------------------------------------------------
This is the good one: optocoupler = ESP32 is isolated from the 12V (light, not
wire). Solves the ground/noise/smoke problems.

INPUT header (8-pin: GND IN1 IN2 IN3 IN4 IN5 IN6 VCC) -> to ESP32:
| Relay pin | Wire to |
|-----------|---------|
| IN1       | GPIO 32 |
| IN2       | GPIO 33 |
| IN3       | GPIO 25 |
| IN4       | GPIO 26 |
| IN5       | GPIO 27 |
| IN6       | GPIO 14 |
| VCC       | ESP32 5V |
| GND       | ESP32 GND |

POWER header (3-pin: JD-VCC GND VCC) -> to 12V PSU:
| Pin    | Wire to |
|--------|---------|
| JD-VCC | 12V + |
| GND    | 12V - |
| VCC    | leave empty (fed by the 8-pin VCC) |
| JUMPER | *** REMOVE the plastic jumper cap *** |

LOAD (the Peltier), on the SCREW terminals (NOT the header pins):
  12V+  -> COM
  NC    -> Peltier(+)
  Peltier(-) -> 12V-
  (load on NC = cooling ON by default; opens/OFF at 25C)

WIRE GAUGE:
  - IN/VCC/GND/JD-VCC  = thin Dupont / 22 AWG is fine (tiny current)
  - COM -> NC -> Peltier -> fans  = THICK 16-18 AWG (this carries ~6-7A!)
  - The smoke last time = thin 22 AWG + a bad solder joint on this 7A path.

CODE:  RELAY_BOARD_ACTIVE_LOW = true   (opto triggers on LOW)

--------------------------------------------------------------------------------
 5) RELAY WIRING — BOARD B: 4-CH 12V HIGH/LOW (red, male pins) — BACKUP
--------------------------------------------------------------------------------
Transistor board (JQC-3FF-S-Z 5VDC relays). No optocoupler isolation -> it NEEDS
a common ground. More finicky; use only if the opto board fails.

| Relay pin | Wire to |
|-----------|---------|
| IN1       | GPIO 32 |
| IN2       | GPIO 33 |
| IN3       | GPIO 25 |
| IN4       | GPIO 26 |
| VCC       | ESP32 5V |
| GND       | ESP32 GND  AND  12V-  (COMMON GROUND required here) |
| DC+ / power | 12V + (COIL power) |

HIGH/LOW jumper (black header, columns S1-S4, rows High/Com/Low):
  - Put the jumper on Com<->HIGH for each channel used (so it energizes on HIGH)
  - Then in code set RELAY_BOARD_ACTIVE_LOW = false
  - OR jumper on Com<->LOW + RELAY_BOARD_ACTIVE_LOW = true
  - (Match the jumper and the code, or the relay defaults to the wrong state.)

IMPORTANT: those relays are 5VDC COIL. Feed the COIL side ~5V, NOT 12V. The
Peltier (12V load) still goes through COM/NC (contacts handle 12V fine).

  sudo nmcli connection up "hotspot"

 7) TRAINING THE NEW MODEL (Colab notebook)
--------------------------------------------------------------------------------
Notebook: ...\Project Design\Weslie_Shelvy_Mold_Training.ipynb  (renamed for you)

DATASET (yours, in Roboflow):  mold ~100-150 · bread ~60-100 · bread+mold ~80-100
  - Classes: bread (fresh) and mold
  - Annotate EACH bread and EACH mold separately (own mask), even in mixed images
  - Use Smart Polygon (SAM) = click, it draws the mask; Label Assist after ~40
  - DON'T annotate the same mold 300x -> keep VARIETY (green + dark, sizes)
  - Turn on Roboflow AUGMENTATION 2-3x to multiply for free
  - Keep ~80-100 FRESH bread examples so it doesn't false-alarm mold on fresh bread

TRAIN (in the notebook): yolov8s-seg, imgsz 640 (or 960 for tiny GREEN mold),
  150 epochs, export ONNX opset 12. Green mold favors higher res; dark mold is
  fine at 640. Since detection is interval-based, 960 won't lag the video.

DEPLOY: download best.onnx -> rename version5.onnx -> copy to Pi ->
  run detect_pi.py with --model version5.onnx --size <same as training> --conf 0.15

 10) EMERGENCY CHEAT-SHEET
--------------------------------------------------------------------------------
- Nothing shows in app?      -> open .../readings/esp32-01/latest ; if stale, a
                                device is offline (reflash + power on hotspot).
- Relay won't switch?        -> check active-LOW matches the board + jumper;
                                buck 5V->VIN; red LED on; temp above setpoint.
- Relay/wire smoked?         -> thin wire on the 7A Peltier path -> use 16-18 AWG;
                                UNPLUG 12V first; check no DC+ <-> DC- short.
- Flash fails / boot loop    -> bare flash, 115200, Erase All Flash, close Serial
  (partition 0 invalid magic)   Monitor, hold BOOT; if still bad, board is dead
                                -> use a spare ESP32.
- Pi wrong WiFi              -> house + hotspot share a name; turn off the wrong
                                one, or rename so they differ.
- Need Claude again          -> upload SHELVY-PROJECT-HISTORY.md to claude.ai and
                                describe the problem.
